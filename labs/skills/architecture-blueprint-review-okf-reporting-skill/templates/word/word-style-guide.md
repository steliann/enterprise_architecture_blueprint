# Word Report Style Guide

This style is derived from the supplied architecture-assessment example while keeping the content generic.

## Page and typography

- Page size: A4 portrait.
- Approximate margins: 0.65 in left/right and 0.58 in top/bottom.
- Body font: **Inter**, approximately 10 pt.
- Body text: dark neutral `#454659`.
- Heading 1: 18 pt, bold, Qlik green `#009845`.
- Heading 2: 12.5 pt, bold, dark green `#007133`.
- Heading 3: 10.5 pt, bold, dark green `#007133`.
- Keep paragraph spacing compact and professional; avoid excessive whitespace in detailed findings.

## Accent palette

- Primary green: `#009845`
- Dark green: `#007133`
- Teal: `#006580`
- Dark text: `#454659`
- Light green fill: `#EAF5EF`
- Light teal fill: `#E6F3F4`
- Light grey fill: `#F3F4F4`

## Tables

- Use teal/green header fills with white bold text for major classification tables.
- Use pale alternating fills or neutral grey for metadata/KPI tables.
- Keep table borders thin and unobtrusive.
- Repeat header rows when a table spans pages.

## Detailed findings

- Start each gap with an uppercase small category label.
- Use the gap title as Heading 1.
- Place a four-cell strip directly beneath the title: Priority, Confidence, Response, Horizon.
- Use Heading 2 for `Architecture finding` and `Recommendation`.
- Use Heading 3 for context, gap, impact, current/strategic paths, benefits and validation.

## Cover and navigation

- Use a clean Qlik-style cover with logo, small `ARCHITECTURE ASSESSMENT` label, customer name in green and report subtitle in dark neutral.
- Include a table of contents in production output.
- Footer: `<Customer> Architecture Assessment | v<version>` on the left and page number on the right.

## QA

Render to page images and inspect all pages. Fix orphan headings, clipped tables, dense single-page finding blocks, excessive blank pages and inconsistent table widths before delivery.
